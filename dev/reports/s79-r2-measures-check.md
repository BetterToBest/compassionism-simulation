# Can v5.9 report the BLEI paper's other measures? (Nov 16, 2026)

**The question.** The visual suite's v5.9 view shows the BLEI series, but its cards for the BLEI paper's other five measures (the Extractive Drain Coefficient, EDC; the Effective Purchasing Power Multiplier, EPPM; the Financial Bandwidth Score, FBS; the Compound Stability Index, CSI; the Indirect Participant Benefit Index, IPBI) and the measures study (who gains, how people move between tiers, wealth net of drain) say they exist for v5.6 only. Before any run, this note checks which of them the engine can report for v5.9's main row (no programme, the full-coverage design, built to meet NEEC's criterion C2.2, and the opt-in design) without changing the model.

**The answer: all of them.**
- **EDC** (share of income paid as rent to landlords and interest on debt). The engine measures it when the measured-EDC switch is on. v5.9's rows did not have it on. It is a reporting switch: it records payments and changes nothing that happens.
- **FBS** (share of participant-years whose monthly surplus reaches the level at which the chance of advancing a tier is even). The engine tallies it when the FBS50 option is on with each adult's own advancement rate, which is the rule v5.9 ran. v5.9's rows did not have the tally on. Its other readings (a different spread or scale) would change the rule, so they are not used.
- **EPPM, the FBS surplus for every adult, CSI and the measures study.** These are computed per adult from quantities the engine already keeps at the end of each year, plus the per-adult flows of the accounting check, against the same adult's run with no programme on the same seed. Reporting only.
- **IPBI** (only partly modelled: the public costs of prisons, hospital and psychiatric stays, and homelessness avoided). This is a calculation from figures v5.9 already stored (the share below the cost of living, the poverty gap, the unhoused share). It is done in the run so the page reads one source.

**How this was checked.** The export tool was extended (`dev/tools/explore_export.js --r2 --study`) and tried on 2 seeds in Reference (20 and 40 years), Adverse (20) and Stress (40). In every test, every one of the 2,931 engine outputs of every row and seed equalled v5.9's stored results (engine 104691f), and the only new outputs were the two switches' own. No accounting identity failed. A change of one part in a trillion to one stored value made the check fail, so the check is live. These were tests of the tool, not results: no figure from them is used.

**What still holds back.** Nothing needs a switch that v5.9 does not have, so no card keeps "v5.6 only". The limits that each card already states still apply: EPPM, FBS and CSI are measured in the model's own terms, not with the paper's formulas; IPBI covers only public costs; the FBS's "even odds" level is a model rule with a provisional range, not an observed rate.
