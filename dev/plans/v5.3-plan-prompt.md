### B1. One engine copy (decision on the dashboard: "one engine copy")

If not, fall back to the hand copy with the 12-row × 154-measure parity test extended to every household measure, and record why.

### B2. Accounting identities as enforced checks (GPT §4)
Today the ledger is reporting-only. Make the identities executable checks (assertions in the unit suite over every release row for a set of seeds, and an optional runtime check off by default), without changing dynamics:
- BU: issued = spent + expired + converted + outstanding (adjust to the engine's actual BU life cycle; every BU has a source and a destination).
- Conversion: BU converted × rate = gross conversion value = tax + worker/creator payout + ESP split (lower prices / reinvestment / profit share) + residual.
- Source/Treasury: programme outlays = taxes + created money + other financing, per the financing mode.
- PTH: housing payment = operating cost + equity contribution + community surplus + financing cost.
- Per person (and per household from B3): ending net worth = beginning + saving + capital gains + net transfers − losses, to a stated tolerance.
Any identity that fails is a finding: fix it as a recorded engine correction (a figure change ⇒ decision), never by loosening the tolerance.

### B4. Children as dependents
Children have age, dependency, childcare need by age, schooling, and a resource share; no autonomous economic choices yet. They age on the ageing stream; births follow NCHS fertility by mother's age on their own stream; at adulthood they enter the adult population in place of the unrelated 25-year-old entrants (when `HOUSEHOLDS` is on), forming their own household at a sourced leaving-home age. Keep partnership formation static (couples as drawn) in this round and say so on the page.

### B5. Estates stay in the model
With ageing on, a death passes the estate to the surviving partner, else children in equal shares, else it leaves the model as now (labelled). No inheritance tax unless the Hub specifies one.

### B6. Household-correlated shocks and a measured EDC
- Income shock = macro × household × person, the household layer on a new stream, so partners can lose income together.
- EDC from flows: extractive outflows (rent, interest, fees as modelled) ÷ gross household income, reported as "EDC (measured)"; relabel the current `agentEDC` formula "EDC (design target proxy)", keeping the existing label that results using the 0.025 CCO-PTH target are conditional on that target being met.

### B7. Calibration, each as a reading first, inside the prescribed mechanics-audit + large-N restudy
