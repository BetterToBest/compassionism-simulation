# Build plan to the single release

Oct 1, 2026. Source: the Simulation ledger (document "sim") as of version 236, plus Duke's Oct 1 delegation. v4.22 stays live and unchanged until the release.

## Design defaults (decided by Claude under Duke's delegation)

These were the questions waiting for Duke. Each is now settled on the default below; the alternatives stay as sensitivity rows where marked.

1. **New output backing the BU.** Two kinds, each with its own rule: capacity that essential-service businesses build with reinvested earnings (more essentials supplied, so lower prices over time), and project work counted at the cost of the hours and materials it pays for, but not as essentials supply. Capacity takes as long as it takes reinvestment to reach the 2025 capital stock of the Hub's essential-service industries per adult ($18,862, BEA and Census; about year 5 at Reference). The old "every reward matched by output" setting (H1) stays as a sensitivity row.
2. **How Compassionism pays for itself.** As the Hub states it: BU issued by a Source/Treasury, with the conversion tax and unspent BU returning to it, replacing the flat wage contribution. Read the Hub's financing text first and write "Claude's reading" in `dev/reports/` before code. The flat contribution stays as a sensitivity row. Checkpoint after this step: write a short report of where the results stand.
3. **Joining and leaving.** Open enrolment each year: an adult joins when the BU they would receive exceeds what they would pay. Minimum stay 2 years, rejoining allowed, no fee (a modelling assumption; sweep 1 and 5 years). Emergency enrolment on shocks stays as built.
4. **Moving up an octave.** Keep today's rule (advancement gated by financial stability), label it plainly on the page, and test slower advancement (for example one octave per 3 years) as a sensitivity.
5. **Capital and running costs of community-owned businesses and housing.** As the Hub states it (read it first, write Claude's reading): community business capital comes from the ESP split's reinvestment account; running costs and community housing capital are costed from sourced figures (BEA, Census). "Price cuts free" stays as a sensitivity row.
6. **Nothing changes on the live page before the release**, including the three wording corrections.
7. **The main page shows a precomputed 500-seed panel** beside the live run (three environments, with intervals), regenerated by the harness at the release with its command named.
8. **BLEI as Duke's BLEI paper defines it heads the page**, with the design-neutral reading beside it, labelled. Confirm this when the BLEI step's results are in.
9. **Engine code stays in the single file** `index.html`; `harness.js` stays a separate copy, kept equal by the three checks plus a new same-seed page-versus-harness comparison.
10. **Unreleased work lives on the branch `next-release`.** (The earlier plan was a folder the live site does not publish; a branch is that plan's stated fallback and is safer for Claude Code, which commits often.)

## Build order

Each step: design note (plain words) → build behind a switch → unit tests → three checks → 500-seed paired restudy in three environments → plain-words report in `dev/reports/` → update `PROGRESS.md` → commit and push.

0. **Page outline.** A plain-words outline of the released page: what Compassionism is, then a live run; one everyday sentence per result; a short honest list of limits; what moves to the replication page (version history, calibration notes); what leaves with the comparison (the "Compare designs" controls, the six-design table, the "What each design is" sections saved as an unlinked draft file, every "five other designs" line, the walk-through link in the README). Show no interim headline numbers. Do not wait for Duke's reply; proceed.
1. **ESP split** (where essential-service businesses' converted earnings go). Fully designed and sized in `dev/background/N1-design-esp-surplus.md`, section 8 gives the code switches, tests and restudy rows. Privately owned ESPs: owners keep all of a private business's earnings (Duke confirmed Oct 1); size it.
2. **Production side** (design default 1 above).
3. **Financing** (design default 2). Checkpoint report after it.
4. **Joining and leaving** (design default 3).
5. **Capital and running costs of community businesses and housing** (design default 5).
6. **Octave rule** (design default 4).
7. **Spending rule.** Let people spend some income above the cost of living (today they save every dollar; the simulated population saves 44% against about 3-6% in the US). Source the spending rate.
8. **BLEI-led reporting.** Make BLEI (days of basic living covered) the headline measure; confirm design default 8 with the results in front.
9. **Avoided public costs.** Public costs of poverty avoided (crime, homelessness services, emergency and institutional health care) beside the program's cost; each figure from primary sources, both sides shown where contested.
10. **Port into the page.** Port the finished mechanisms into `index.html`'s engine, with a same-seed check that page and harness agree.
11. **Restudy.** 500 paired seeds, three environments, every mechanism in; every gain confirmed on basket and wealth poverty; poverty, cost, work, prices and groups.
12. **Page items.** Remove the comparison; move version history and calibration notes to the replication page and keep a short list of limits on the main page; fix the three wording problems (the "Four Measures" card is "Five"; the BU glossary's "PTF only"; the 30% efficiency label, checked first); add the attribution (in `CLAUDE.md`) under the page title, in the README and on the replication page.
13. **Release prep.** Update README, CONTRIBUTING, the replication page and the Hub index files; propose the version label (4.23 or 5.0). Then stop and tell Duke the gate status. Merge to `main` and tag only after Duke says "release".

## Release gate

Everything above built; the 500-seed restudy done in three environments; gains confirmed on basket and wealth poverty; the three checks pass; page and harness agree on the same seeds; Duke has read the restudy report. The live octave wage raise and inflation slow-down are off by default (each a labelled switch), no program is compared at the scenario's own inflation, and the current conversion design is named plainly.
